## 1. Как VS Code подключает плагины

Плагин VS Code — это пакет Node.js с файлом `package.json`. Главное в нём:

| Поле | Зачем нужно |
|---|---|
| `main` | файл, который VS Code загрузит (`out/extension.js`) |
| `activationEvents` | когда запускать плагин: при открытии файла на `cpp` или `c` |
| `contributes.commands` | команды в палитре `Ctrl+Shift+P`: открыть рулетку, сдаться |
| `contributes.configuration` | настройки: `checkCommand`, `skipMain`, `minLines` |

Плагин работает в отдельном процессе **Extension Host** и общается с редактором через API `vscode`.
Возможности API, которые использует Code Roulette:

| API | Для чего |
|---|---|
| `window.createWebviewPanel` | панель с рулеткой — это HTML-страница внутри VS Code |
| `webview.postMessage` / `onDidReceiveMessage` | обмен сообщениями между плагином и панелью |
| `window.createStatusBarItem` | кнопка «🎰 Рулетка» и таймер в строке состояния |
| `WorkspaceEdit` + `workspace.applyEdit` | стирание и возврат тела функции |
| `workspace.onDidChangeTextDocument` | слежение за правками (защита от Ctrl+Z) |
| `ExtensionContext.globalState` | хранение статистики между запусками |
| `ExtensionContext.globalStorageUri` | папка для резервной копии функции |
| `child_process.exec` (Node.js) | запуск команды проверки (сборка + тесты) |
| `window.onDidChangeWindowState` | уход из VS Code в другие программы (журнал) |
| `window.showInputBox` / `showQuickPick` | настройка экзамена практиком, ввод PIN |
| `activationEvents: onStartupFinished` | плагин стартует вместе с VS Code и продолжает незаконченный раунд |
| `crypto` (Node.js) | хеш PIN-кода SHA-256 |

## 4. Конечный автомат состояний (`game.ts`)

```mermaid
stateDiagram-v2
    [*] --> idle
    idle --> spinning: КРУТИТЬ
    spinning --> solving: колесо остановилось
    spinning --> idle: функция исчезла
    solving --> checking: ГОТОВО
    solving --> finished: время вышло / сдался
    checking --> finished: результат проверки
    finished --> idle: ЕЩЁ РАЗ
```

Допустимые переходы хранятся в таблице `Map<GameState, GameState[]>`, а функция
`canTransition(from, to)` проверяет переход. Поэтому, например, повторное нажатие
«ГОТОВО» во время проверки просто игнорируется.

## 5. Поиск функций (`parser.ts`)

### Шаг 1. Очистка — `cleanCode(text)`

Конечный автомат проходит по тексту и заменяет пробелами комментарии `//` и `/* */`,
строки `"..."`, символы `'...'` и директивы `#include`. Длина текста не меняется,
поэтому позиции символов совпадают с исходным файлом. Это нужно, чтобы `{` внутри
строки `"{ not a brace }"` или функция в комментарии не сбивали разбор.

### Шаг 2. Стек скобок — `findFunctions(text)`

Идём по очищенному тексту и храним стек открытых `{`:

| Встретили | Действие |
|---|---|
| `{` | если мы не внутри функции и текст перед скобкой похож на заголовок — это начало функции, кладём в стек `true`, иначе `false` |
| `}` | снимаем со стека; если сняли `true` — нашли конец функции |
| `;` | запоминаем границу: заголовок следующей функции начинается после неё |

Заголовок распознаётся регулярным выражением `имя(параметры) const ...`, слова
`if`, `for`, `while`, `switch` функциями не считаются. Метки `public:` / `private:`
и список инициализации конструктора `: x_(x)` отбрасываются.

Результат — список `FunctionRange`:

```ts
interface FunctionRange {
    name: string;        // имя функции
    signature: string;   // заголовок одной строкой: "int sum(int* a, int n)"
    headerStart: number; // где начинается заголовок
    open: number;        // позиция {
    close: number;       // позиция }
    bodyLines: number;   // непустых строк в теле
}
```

## 6. Выбор функции (`game.ts`)

`pickIndex(names, recent)` выбирает случайную функцию, кроме тех, что лежат в очереди
`recent` (последние 3 выпавшие). Если все функции недавно выпадали, выбор идёт из всех.
Очередь обновляет `pushRecent`: новое имя добавляется в конец, самое старое удаляется.

## 7. Защита от читерства

Во время раунда плагин слушает событие `onDidChangeTextDocument`. Для каждой правки
вызывается `looksLikeOriginal(вставленный_текст, оригинал)`:

1. из обоих текстов убираются все пробелы и переводы строк (форматирование не важно);
2. вставка короче 30 символов — не чит (так печатает человек);
3. если вставка целиком лежит внутри оригинала (Ctrl+Z, вставка части) или оригинал
   целиком лежит внутри вставки (откат файла, вставка целого файла) — это чит.

При чите `punishCheat()` снова стирает тело функции, сдвигает время старта на 30 секунд
и показывает на панели баннер «🚫 ЧИТЕР!» с тряской экрана. Свои правки (стирание,
возврат оригинала) плагин делает с флагом `ownEdit`, чтобы не поймать самого себя.

## 8. Раунд переживает закрытие VS Code

Раунд (`Round`) — обычный объект без ссылок на VS Code: адрес файла, стёртые функции с оригиналами,
время старта, штрафы, журнал. Он сохраняется в `globalState` при каждом событии и раз в 5 секунд
(поле `lastSeen` — «я жив»).

При запуске VS Code (`onStartupFinished`) плагин вызывает `resumeRound()`:

```mermaid
flowchart TD
    A[VS Code запущен] --> B{на диске есть раунд?}
    B -- нет --> Z[обычный старт]
    B -- да --> C[closed = сейчас − lastSeen]
    C --> D[в журнал: 🔌 VS Code был закрыт closed сек]
    D --> E{время раунда вышло?}
    E -- да --> F[поражение: время вышло, пока VS Code был закрыт]
    E -- нет --> G[таймер продолжается, панель открывается]
```

Таймер считает от `startedAt` по реальным часам, поэтому закрытие VS Code время не останавливает.

## 9. Журнал раунда (`journal.ts`)

Событие — `{ at, kind, value, text }`: секунда раунда, вид, число (секунды или символы) и пояснение.

| Вид | Когда пишется | value |
|---|---|---|
| `start` | раунд начался | — |
| `focus` | окно VS Code вернуло фокус после ухода ≥ 3 сек | секунды вне VS Code |
| `paste` | одна правка вставила ≥ 30 символов (без пробелов) | число символов |
| `cheat` | вставка похожа на оригинал (Ctrl+Z и т.п.) | — |
| `closed` | VS Code перезапущен посреди раунда | секунды, пока был закрыт |
| `hint` | взята подсказка | номер подсказки |
| `finish` | раунд закончен | — |

`summarize(events)` проходит по списку и считает итоги, `suspiciousLines` превращает их
в строки для экрана результата и отчёта.

## 10. Сложность, подсказки, достижения (`modes.ts`)

**Сложность.** `allowedIndexes` считает медиану длины тела функций файла:
лёгкий уровень берёт функции не длиннее медианы, адский — не короче. `pickTargets` выбирает
одну функцию, а на адском — две разные (колесо крутится дважды, «⚡ двойной удар»).

**Подсказки.** `hintLines` берёт непустые строки оригинала (без одиночных скобок). Каждая
подсказка сдвигает время старта на 60 секунд и пишется в журнал.

**Достижения.** Список `ACHIEVEMENTS` (9 штук). `newAchievements(итоги, открытые)` проверяет
условия и возвращает только новые; открытые хранятся в `globalState`.

## 11. Режим экзамена

```mermaid
sequenceDiagram
    participant P as Практик
    participant E as extension.ts
    participant S as Студент
    P->>E: «Начать экзамен»: ФИО, раунды, время, сложность, подсказки, команда, PIN
    E->>E: createExam: PIN → SHA-256(соль + PIN), команда зафиксирована
    loop каждый раунд
        S->>E: КРУТИТЬ → пишет функцию → ГОТОВО
        E->>E: результат + журнал раунда → exam.results
    end
    E->>E: buildReport → roulette-report-*.md
    E->>P: отчёт открывается в просмотре Markdown
```

- Экзамен хранится в `globalState`, поэтому тоже переживает перезапуск.
- Пока идёт экзамен, время и сложность берутся из настроек практика, кнопки на панели скрыты.
- «Остановить экзамен» требует PIN: `checkPin` сравнивает хеши. Неверный PIN попадает в журнал.

### Замок практика

После каждого раунда экзамена `finish()` не показывает результат, а **запечатывает** его:
сообщение с результатом сохраняется в поле `exam.sealed` и вместе с экзаменом пишется в `globalState`.

```mermaid
stateDiagram-v2
    solving --> sealed: ГОТОВО / время вышло / сдался
    sealed --> sealed: неверный PIN (wrongPins + 1)
    sealed --> result: верный PIN — unlock()
    result --> solving: следующий раунд
    result --> report: последний раунд — отчёт
```

- Пока `exam.sealed` есть, `spin()` отказывает, а при запуске VS Code плагин сразу показывает замок —
  поэтому перезапуск или другая папка его не снимают.
- `unlock(pin)` проверяет PIN; неверные попытки считаются в `wrongPins` и попадают в текст раунда в отчёте.
- На время раунда включается Zen Mode (`workbench.action.toggleZenMode`), после экзамена — выключается.

## 12. Проверка решения

По кнопке «ГОТОВО» файл сохраняется, и команда из `codeRoulette.checkCommand` запускается
через `child_process.exec` в папке проекта (тайм-аут 3 минуты). Код выхода `0` означает победу.
Вывод команды пишется в панель **Output → Code Roulette**. Если команда не задана,
победа засчитывается по времени.

## 14. Тестирование

`src/test/run.ts` содержит 31 тест: поиск функций (методы классов, конструкторы,
комментарии, скобки в строках), границы и сигнатуры, автомат состояний, выбор без
повторов, очередь недавних, формат времени, статистика, распознавание читов, журнал,
уровни сложности, подсказки, достижения, PIN и отчёт экзамена.

```bash
npm test
```

Панель можно открыть и в обычном браузере: без VS Code `roulette.js` включает демо-режим
с выдуманными функциями (а с `#exam` в адресе — и с экзаменом). Так удобно проверять дизайн.
